# 事件介绍的编辑约定

事件介绍面向在地图和时间中探索历史的普通读者。正文要让读者理解具体发生了什么、各方为什么行动、变化怎样形成；语言平实、准确，有叙述感。史料、日期、地理与来源维护规则见[数据维护](data.md)，本文只说明写作选择。

## 先找事件的重点

逐篇判断值得解释的问题，再选择叙述顺序与小标题。战争可侧重联盟、补给、地形与关键行动；改革可解释措施怎样执行、影响哪些人、遇到什么阻力；文化和知识事件可从创作、研究、交游或作品流传切入。这些是可选角度，同类别的事件也不必采用同一结构。

开头让读者迅速知道时间、地点、主要人物及核心变化。正文把具体行动和因果连接起来，必要的时代背景放在读者需要它的位置。小标题应说明本节内容；可有多个，也可完全不用。不固定套用“经过、局势、影响”，不要求每篇都有相同栏目。

## 篇幅由内容决定

没有统一目标字数、最低篇幅或按重要性分配的固定档位。简单事件讲清即止；复杂事件在材料足够时多写。新增段落应带来新的行动、解释、证据或必要背景；删去重复摘要、泛泛评价和为凑字数补入的时代常识。

已确认的阅读参照是 `src/data/event-narratives.ts` 中的赤壁、商鞅与兰亭三篇：战局叙事、制度解释和连续文化叙述可以并存。参考它们的清楚程度和阅读节奏，不复制段落数量或标题形式。

## 叙述与史料分寸

- 交代谁做了什么、行动条件及后续应对；不编造对白、心理、现场细节或精确数量来制造故事感。
- 区分当时的直接结果、后续发展与长期影响。避免把后来的变化全部归于单一事件，也不把后来形成的格局写成当日已经完成。
- 正文中的解释应有相符的基础出处；资料充足、事实明确的常见事件可直接依据已有可靠资料撰写，不必逐篇重做多方考证。关键事实、年代或来源有疑点时再补查；有立场的原典用“据……记载”等表明来源，不把原典评价直接写成编辑结论。
- 影响核心理解的争议随句交代；其他必要辨析放入简短的文末说明。避免让整篇被“不能理解为”“不意味着”等纠偏语句占据。
- 世界史同样逐篇选择写法。尊重各地区自身的时序与行动者，解释必要的制度和名词，保留原住民及被殖民者的经历；不把欧洲经验当成所有地区的共同进程。
- 地理确实影响事件时，说明河流、山口、城市、交通或资源为何重要。地图上的代表坐标不转写为所有活动的精确现场。

## 落稿与检查

独立正文使用 `narrative.sections`，标题可选，段落数不限；有必要才写 `narrative.note`。来源使用可定位的卷次、文献、档案、机构页面或可靠基础条目，保留与正文相符的出处。保留既有来源与新近实际复核是不同状态，未重新核验时不声称已经核验。不要把“有链接”“抓取成功”或结构校验当成史实已核对。

逐批维护和审校，报告本批实际完成的事件范围。尚未改写的记录保留现有介绍，不用自动拆分旧字段或机械加标题冒充完成。按[数据维护流程](data.md#审校与缓存)集中更新派生清单。纯正文批量改写不逐篇运行浏览器或截图；界面和渲染逻辑有变化时，再按贡献指南检查相关布局。
